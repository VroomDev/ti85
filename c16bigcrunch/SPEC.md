# Crunch — Commodore 16

Action game by Chris Busch (1995/96). 16KB Commodore 16 port. Levels are generated mazes.

**Living spec.** Update this file whenever behavior is locked or fixed.  
**Gameplay** matches `[reference/CRUNCH.ASM](reference/CRUNCH.ASM)` except the map source: there are no packed levels and no drip spawn.

---

| Item      | Value                                            |
| --------- | ------------------------------------------------ |

| Video     | TED, 40×25. PAL and NTSC (delays are in VBlanks) |

| Toolchain | `%USERPROFILE%\cc65`, config `c16-crunch.cfg`    |

After building, report free RAM from the end of BSS to `$4000`.

## Display

| Item       | Value |
| ---------- | ----- |
| Screen     | `$0C00` |
| Color RAM  | `$0800` |
| Charset    | RAM `$2000`. Copy ROM `$D000` first, then point TED here. |
| Code       | `$100D`–below `$2000` (MAIN). Stub `$1001`, `SYS 4109`. Optional **CODEHI** in upper RAM after the PRG pad. |
| Playfield  | `$2800`, 512 bytes |
| Upper RAM  | `$2A00`–`$3FFF`: CODEHI (if any), then BSS (maze stack, vars). The PRG pads `$2000`–`$29FF` so load is contiguous; charset and playfield overwrite that pad at runtime. |
| Vars       | Most state in BSS (upper RAM). Zeropage only for 6502 `(ptr),y` pointers (`$D8`+). `load_level` runs with IRQs off. |

- `$FF13` bits 7–2 = charset A15–A10 (`$20` for `$2000`). `$FF12` bit 2 clear so TED reads RAM.
- Background `$FF15` and border `$FF19` are black.
- TED color byte: luminance in bits 6–4, chroma in bits 3–0. Bit 7 is flash; leave it clear.
- Bitmap 1 = color RAM, 0 = background. Do not mask color with `and #7`.
- Tiles `$60`–`$6F` installed bitmaps; wander facing `$70`–`$73` is map-only. Never redefine A–Z. Empty = `$00` (blank glyph). Coin is screen code `$1B`, two editable bitmaps that start as the PETSCII filled circle. Heart = ROM `$53` at `$1C`.
- Hardware cursor parked past cell 1000 so it does not cover the playfield.
- Poke screen and color RAM only in VBlank. Poll raster `$FF1D` / `$FF1C` bit 0.

### Playfield (40×25)

| | |
| --- | --- |
| Map size | **32×16** |
| Origin col | **4** |
| Origin row | **4** |

```
Col:  00    04                          35    39
Row 00 +----------------------------------------+
       | C16 BIG CRUNCH / (C)1996 CHRIS BUSCH   |
Row 04 |    +------------------------------+    |
       |    |         32×16 playfield      |    |
Row 19 |    +------------------------------+    |
Row 21 |    S:dddd  heart  L:dd    HI:dddd      |
Row 24 |     PRESS 1 OR 2 TO START GAME         |
       +----------------------------------------+
```

Title stays when a game starts. **C16 BIG CRUNCH** centered on row 0. **(C)1996 CHRIS BUSCH** centered on row 1. On the first intro only, row 21 centers `vYYYYMMDD` (column 15), the build date from `src/version.s`. StartLevel clears those nine cells and draws the score line. Later intros leave that row blank except the high score. Score, lives, level, and high score are centered on row 21: `S:` at column 5, then the 4-digit score, heart, `L:` + 2-digit level, and `HI:dddd` at column 28, including when the high score is 0. **PRESS 1 OR 2 TO START GAME** (26 chars) centered on row 24 on the title and after game over; wipe those cells on StartLevel. **next** is four characters at screen center (row 12). **pause** is five characters at the same center. The game starts on level 1.

## Gameplay

1. **Player** — **2×2**, top-left anchored (9-bit index). Up/down add `-PF_COLS` / `PF_COLS`; left/right add −1 / +1; mask 511. Move one step every other frame while a direction is held. Leading edge is two cells (same rule as monsters). Walkable: empty, blood, or coin. Stepping on blood clears it. A coin under the footprint scores +1 once. Health +1 when the last two score digits are 49 or 99 (cap 9). Fire in the last facing direction; fire held aims and does not walk. Bullet spawn alternates each shot between the two cells on the facing edge (up: TL/TR, down: BL/BR, left: TL/BL, right: TR/BR). Players are solid on any quadrant; a bullet that hits any player cell stops with no damage. Blit: top row yellow, bottom cyan; all purple while hurt.
2. **Monsters** — big ones are **2×2**, top-left anchored. Placed by the generator before the level starts. There is **no drip spawn** and no shared spawn cell. A big TL cell, or any little monster cell, triggers movement when `spot` lands on it.
3. **Bullet** — one shot per player (`bulletdir == 0` to fire). Steps every frame. Max **4** tiles, then the last cell is erased. Hit any big quadrant → resolve TL and split the 2×2 into four 1×1 monsters (wander keeps wander; chase keeps chase; a coin cell is left as the coin). A little wander becomes a little chase. A little chase becomes blood. Chase splits and little deaths play the kill sound. No score on a hit. Killing monsters does not clear the level.
4. **Levels** — generated, 1-based, cap **99**. Last coin: erase each remaining big monster (TL only, full 2×2 clear) and each little monster (that cell), `inc_score` twice (+2, chirp each) with blit and HUD, then show **next** (do not clear the screen). Wait **39** VBlanks, then StartLevel.
5. No quit. No bomb. **SPACE = fire** (same as **K**).
6. **Two-player co-op** — on the title / game-over wait: digit **1** or joystick port 1 fire starts one-player; digit **2** or joystick port 2 fire starts co-op (`two_player = 1`). Shared score, health, and `hurt_dur`. Two independent 2×2 players and bullets. P1 TL at index **240** (col 16, row 7); P2 TL at **243** (`P2_SPAWN_OFF = 3`), one empty column between the footprints. The start box is 7×4, top-left one row above and one column left of P1. `O` is a coin, the blank column is the empty gap:

```
OOOOOOO
OXX XXO
OXX XXO
OOOOOOO
```

That gap is reserved so a maze cannot wall the players against each other. In one-player the coin ring is still the eight neighbors of the spawn footprint (spawn cells get no coin). P1: keyboard + joystick port 1. P2: joystick port 2 only. In one-player, both joystick ports stay OR’d with the keys (unchanged).

### Controls

| Action   | Key                |
| -------- | ------------------ |
| Up       | **I**              |
| Left     | **J**              |
| Down     | **M**              |
| Right    | **L**              |
| Fire     | **K** or **SPACE** |
| Pause    | **P** — freezes play, shows **pause** at screen center; **P** again resumes |
| Joystick | 1P: either port, OR’d with the keys. 2P: port 1 + keys → P1; port 2 → P2 |
| Start 1P | Digit **1** or joystick port 1 fire on the title / game-over wait |
| Start 2P | Digit **2** or joystick port 2 fire on the title / game-over wait |
| Code    | **C** shows **?** at column 0 of row 24 and arms the cheat for the **current level only** (cleared on StartLevel). **B** then sets the score to 0 and takes the normal next-level path, once per press |

Keys are the TED matrix (`$FD30` select, `$FF` on `$FF08`, read `$FF08`). Joysticks are `$FF` on `$FD30`, then `$FB` (port 1, fire bit 6) or `$FD` (port 2, fire bit 7) on `$FF08`. Active low. Digits **1** and **2** are column `$7F` bits 0 and 3. Title and game over wait for those start inputs, then for release.

### Monster movement

Each frame, `update_monsters` keeps going while `steps < SPOT_STEPS` (**200**) and the TED raster (`$FF1D`) is neither **123** nor **126**. Then `spot = (spot + 183) & 511`. A **top-left** big monster tile, or a little monster, on that cell tries **one** cell slide (same index add as the player). Big body cells never initiate a move. The bullet uses that add too.

A slide checks the two destination-edge cells (e.g. down → the two cells immediately below the 2×2). Coins block every cell of the 2×2. Uncomment `FEET_BEHIND_COINS` in `game.inc` to let only the lower half (BL and BR) step behind a coin. The coin character stays in that cell, in front of the monster; the monster glyph is not written there. The top row still may not land on a coin: up rejects a coin on either new top cell, left rejects a coin on the new TL, right rejects a coin on the new TR and also when the current TR is a coin, and down rejects the step when the current BL or BR is a coin. Allowed cells clear → clear the old 2×2, stamp the new 2×2, skipping any coin. With the switch on, the footprint looks like this (`c` is the coin character):

```
MM    MM
Mc    cM
```

The player still collects that coin. Clearing or restamping the monster leaves it alone. Either edge cell is a player half → hurt only if `hurt_dur == 0`. Otherwise blocked: wander picks a new facing and sits; chase tries one random direction with the same edge check. A hurt sets `hurt_dur` to `HURT_PERIOD` (10). Each game cycle decrements it while it is nonzero. While it is nonzero both player cells are drawn purple. Do not walk onto trees, bricks, blood, bullets, or other monsters. The mask wraps at 512. The playfield edge is trees, so a step off the board is blocked until a bullet clears one of those trees.

| Type | Behavior |
| ---- | -------- |
| Wander `$70`–`$73` (TL) | Walk the facing direction until blocked, then pick a new facing and restamp the 2×2 |
| Chase `$6A` / `$74`–`$77` (TL) | Facing is stored on the TL like wander (`$74`–`$77`, blit → `$6A`). Each step: if `frame & 7`, then seek when `coinsleft ≤ level` else patrol (stored facing); if `frame & 7 == 0`, random re-face. Idle blocked → turn in place; aggressive blocked → one random step retry |
| Little wander `$7A`–`$7D` | 1×1, original 8×8 glyph in red. Walk the facing direction until blocked, then pick a new facing. Do not step on coins |
| Little chase `$79` | 1×1, original 8×8 glyph in purple. If `coinsleft ≤ level`, seek the nearest player; otherwise pick a random direction. Blocked by anything but the player → one random step |

A shot on a big monster clears the 2×2 and plants four little monsters of the same kind. Wander facings spread: TL up, TR right, BL down, BR left. A coin in the footprint stays, and that cell does not get a little monster.

Installed tiles `$60`–`$6F` each have two bitmaps. The two brick bitmaps are identical. The coin at `$1B` has two bitmaps, `coin` and `coin1`, both the PETSCII filled circle. Little monsters `$78`–`$79` are the original 8×8 wander and chase, each with a second pose. `blit_playfield` increments `frame` and installs `tiles1`, `coin1`, and `little1` when `frame & 16` is set, otherwise `tiles`, `coin`, and `little`. Wander facing blit-remaps to `$66` in red; little wander facing blit-remaps to `$78` in red; wander/chase body glyphs keep their codes; chase and little chase are purple. A bullet splits a big monster into four little ones. A little wander becomes a little chase, and a little chase becomes blood.

## Maze

`load_level` builds a 30×14 maze centered in the 32×16 playfield. Walls and hallways are **2 cells thick**. The carve runs from row 3, column 3 with **step 4** (one cell in from the old lattice so halls sit cleanly inside the tree hedge). The playfield edge (row 0, row 15, column 0, column 31) is a 1-cell tree hedge and does not move. A bullet clears a tree, so a shot opens a hole in that hedge. Wall marker is brick (`$61`). Open marker is empty (`$00`).

1. If `SEED_LEVEL_RAND` (`game.inc`): seed the 8-bit LFSR with the level, or **255** if the level is 0; when the level is greater than 98, leave it as it is. If unset: leave both LFSRs as they are (title / game-over wait advances them).
2. Fill the field with empty cells. After placement, the playfield edge is planted with trees.
3. Depth-first wall lay from row 3, column 3, step 4: each room and the halfway block become a **2×2** of brick. A neighbor is used only when its full 2×2 is still empty and in-bounds (neighbor TL row 3..11, col 3..27). `MAZE_ROOMS` = **21** (rows 3,7,11 × cols 3,7,…,27). Frames live in BSS.
4. If `SEED_LEVEL_RAND`: seed `rng16` the same way (level, or 255; high byte 0). Then advance `rand16` once before placement draws cells.
5. Player 1 TL at column 16, row 7 (index 240); the 2×2 stays empty. In two-player, P2 TL at 243 and its 2×2 are forced empty. The whole 7×4 start box is reserved, then stamped as the coin border with an empty interior.
6. In one-player, every in-bounds **empty** cell of the eight neighbors around the spawn footprint becomes a coin. Spawn cells themselves get no coin. In two-player the stamp in step 5 replaces that ring.
7. For each batch (capped): two wanders and two chases need a free interior **2×2**; coins need one empty cell. `rand512` then `SPOT_STRIDE` (**183**) with `& 511` until found or a full lap fails. Edge cells are skipped. A failed placement is skipped. Trees still replace random brick cells.
8. `place_space` punches **2-wide** hallways (`min(level,16) << 2`). Each one finds a horizontal brick pair with a 2-cell empty opening above or to the left. Empty above: punch down clearing two side-by-side bricks per step. Empty left: punch right clearing two stacked bricks. If both, punch down.

After the hedge is planted, `count_coins` sweeps all 512 playfield cells and sets `coinsleft`. Wander facing is bits 9–10 of the `rand16` value that chose the cell.

Directions `{0,1,2,3}`, offsets `DR = {-4,4,0,0}`, `DC = {0,0,-4,4}`; halfway `±2`. One `fast_rand` byte shuffles them:

- `j3 = (r >> 1) & 3`, swap 3 with `j3`
- `j2 = (r >> 3) & 3`; if `j2 == 3` then `j2 = 2`; swap 2 with `j2`
- `j1 = (r >> 5) & 1`, swap 1 with `j1`

A neighbor 2×2 is walled only when it is still empty. The halfway 2×2 is bricked first.

## RNG

Never store 0.

**8-bit** `fast_rand`. Boot value `$AC`. Shift right; if the old low bit was set, XOR `$FA`. The LFSR itself never stores 0. The value returned in A is `(lfsr ^ (++whitener))` with an 8-bit `whitener` counter (output may be 0).

**16-bit** `rand16`. Boot value `$00AC`. Shift right; if the old low bit was set, XOR `$D008`. `rand512` is `rand16() & 511`. `load_level` advances it once before placement. The player is not placed from it.

`WaitFireOrKey` (title) advances both generators every poll, and rebuilds/blits a maze every **60** jiffies. Starting 1P keeps that maze; starting 2P rebuilds once for the co-op spawn ring. `StartGame` does not call `LoadLevel` again. `SEED_LEVEL_RAND` in `game.inc` (default 0) makes `load_level` reseed both from the level instead. In-game random facing is `rand_dir`: `((fast_rand >> 1) & 3) + 1` → 1..4. Cell picks use `rand512`.

## Main loop

```
InitGraphics
Silence
hiscore = 0
lfsr = $AC
rng16 = $00AC

Intro:
  level = 1
  LoadLevel
  ClearScreen
  DrawTitle
  DrawHiscore
  if first load: DrawVersion    ; vYYYYMMDD centered, then latch off
  WaitVBlank
  BlitPlayfield
  WaitFireOrKey       ; each poll: fast_rand + rand16; every 60 jiffies: LoadLevel + blit; 1/joy1 → 1P (keep maze); 2/joy2 → 2P (LoadLevel again); wait release

StartGame:
  Silence
  score = 9999 BCD
  health = 7
  level = 1
  goto StartLevelReady          ; maze already built by WaitFireOrKey

StartLevel:
  LoadLevel
StartLevelReady:
  IncScore
  InitSprites          ; one or two players
  ClearOver
  ClearVersion
  DrawHiscore
  DrawHud
  UpdateHud
  WaitVBlank
  BlitPlayfield

GameLoop:
  ReadInput
  UpdatePlayer (slot 0)
  UpdateBullet (slot 0)
  if two_player: UpdatePlayer (slot 1); UpdateBullet (slot 1)
  UpdateMonsters
  WaitVBlank
  BlitPlayfield
  UpdateHud
  if P: Silence; DrawPause; wait P release; wait P; wait P release; BlitPlayfield
  PlayAudioFrame
  if GAMEOVER:  CheckHiscore; DrawGameOver; wait 60 jiffies; goto Intro
  if NEXTLEVEL: DrawNewLevel; wait 39 VBlanks; level++ (cap 99); goto StartLevel
  goto GameLoop
```

## Audio

Three TED cues. Coin = voice 1 tone (`$FF0E` / `$FF11`). Kill = voice 2 noise. Hurt = voice 1 low tone. Silence clears `$FF11` and the frequency registers. Do not zero `$FF12` (charset select lives there). No intro song. No next-level sound.

## Build / run

```bat
build.bat
run.bat
```

`run.bat` starts `xplus4 -model c16 -autostart c16bigcrunch.prg`.

Free RAM is the bytes from the first address after BSS through `$3FFF`. Charset `$2000`–`$27FF` and the playfield `$2800`–`$29FF` are reserved (PRG pad, then runtime fill) and are not part of that count. This build: **685 bytes** (`$3D53`–`$3FFF`).
